# Post-match v2 · #66

## Аудит данных до изменения правил

Проверены `normalizeOpenDotaMatch`, `postMatchEngine`, `carryRules`, domain, существующие combat/economy/benchmark tests и документация. Новые факты проходят через тот же adapter → carryRules → `PostMatchAnalysis`; `matchReview` — модуль представления этих правил, без отдельного движка или новых scores.

| Данные | Решение для #66 | Ограничение |
| --- | --- | --- |
| OpenDota `radiant_gold_adv`, `radiant_xp_adv` | Приводятся к стороне выбранного игрока и общим явным `players[].times`; график и наблюдения | Нет общего однозначного времени или длины расходятся — ряд не используется. Нет интерполяции и подмены отсутствующего нулём |
| Командные драки OpenDota | Проверен фактический пример с `start/end/players`; не добавлены в scoring/causal explanations | Наличие payload не подтверждает все правила участия и соответствие player index. Подробный разбор драк требует отдельной проверки |
| STRATZ combat/deaths | Существующие death timings/coverage и fallback сохранены | Координаты, heroAverage и новые предположения о драках не включаются |
| Объекты | Из существующего payload: точное время, переведённый тип; сторона потерянного строения только по явному имени `goodguys/badguys` | Не определяем героя/команду убийцы из неоднозначного `team`. Смерть рядом с объектом не устанавливает причинность |
| Линия/экономика | Существующая модель и правила; адаптер учитывает явные `times` при приведении массивов к минутам | Выровненный индекс 10 действительно означает 10:00. Пропуски, противоречивые часы и неполный последний интервал не становятся нулями. Provider lane efficiency вычисляется из gold_t[10], поэтому скрывается, если явный times[10] не равен 600 |
| Покупки | Существующие tracked items и ItemTimeline | Сохраняются иконки и время. Нет новых норм предметов; неизвестный тайминг не оценивается |
| Общие GPM/урон | Существующие вторичные оценки | Не превращаются в причину командного поражения. Отсутствующие общие числовые поля больше не подменяются нулём в адаптере |

Семантика проверена по первичному источнику OpenDota, commit `271b0dd914d029acf9a0241499dc826f87d243cc`:

- [Типы и поля](https://github.com/odota/core/blob/271b0dd914d029acf9a0241499dc826f87d243cc/global.d.ts).
- [Compute: сторона, ресурсы и расчёт lane efficiency](https://github.com/odota/core/blob/271b0dd914d029acf9a0241499dc826f87d243cc/svc/util/compute.ts).
- [Опубликованный parsed payload](https://github.com/odota/core/blob/271b0dd914d029acf9a0241499dc826f87d243cc/json/7490235544_parsed.json): временная ось начинается с 120 секунд; есть teamfights и objective events. Это пример shape, не live-проверка контрольных матчей проекта.

Вывод о сдвиге золота выбирает самое большое абсолютное изменение среди полных пяти минут с шестью последовательными минутными срезами. Показываются оба значения, реальный интервал и покупки игрока в нём. Это **возможный фактор**, не доказанная причина. Последний срез описывает финиш только если от него до конца матча не более двух минут. В остальных случаях неполное покрытие обозначается явно. Победа и поражение не меняют личные оценки автоматически.

## Цикл тренировки

- Цель: +5 добитых крипов (включая нейтралов) относительно исходного значения к 10:00. Это явная тренировочная цель, не норма/прогноз победы. Без числового checkpoint цель не создаётся.
- Челлендж добровольный. Сохраняется только в localStorage текущего origin/браузера после нажатия. Нет аккаунтов, БД и фоновой загрузки истории.
- Область: положительный реальный account ID (не 0 и не anonymous sentinel 4294967295), герой, подтверждённая роль керри, game mode, lobby type. Slot не используется как идентичность. Без времени матча/области кнопка принятия недоступна.
- Проверяются загруженные пользователем матчи после принятия цели и после исходного матча. Исходный, старые и чужие матчи не засчитываются; повторный разбор обновляет наблюдение, а не увеличивает счётчик.
- Первые три проверенных матча с checkpoint сортируются по времени матча. Просмотр более раннего подходящего матча может уточнить состав тройки. Это три проверенных матча, а не обещание автоматически найти три ближайших в полной истории.
- Нет checkpoint, матч короче 10 минут или ответ частичный — статус ожидания данных; ни успех, ни провал. Реальный ноль — допустимое наблюдение. После цикла можно явно начать новый или снять цель. Во время принятого цикла показывается сохранённая цель, а не новая цель от каждого просмотренного матча.
- Повреждённая/старая схема хранения не используется; ошибка записи не показывается как успешное принятие. Текст цели восстанавливается из кода. Вкладки одного браузера синхронизируются через storage event.

## Проверка и изображения

`scripts/verify-post-match-v2.mjs` — локальная browser-проверка с Playwright из окружения (не новая зависимость приложения). Матчи строятся реальными normalizer/rules из явно синтетического fixture `postMatchV2.fixture.ts`, внешние providers в harness заглушены. Fixture ID 9000066 не приписывается скриншоту владельца. Числа 561/34 616/51/1 взяты из постановки, остальные данные синтетические.

Запуск: сначала production build/start; затем `PLAYWRIGHT_MODULE_PATH=/path/to/playwright node scripts/verify-post-match-v2.mjs`. `BASE_URL` и `EVIDENCE_DIR` опциональны. `START_SERVER=1` запускает production-сервер в том же процессе проверки. `CHROMIUM_MODULE_PATH` позволяет использовать локальный Chromium вместо загрузки Playwright. Скрипт проверяет 320/390/768/1440/1920/2560, отсутствие горизонтального скролла, выбор матча/игрока, устаревшие ответы, keyboard/focus, controlled errors, loading/empty/partial/unsupported role и цикл челленджа. Снимки помечены как синтетические.

Результаты и изображения: [галерея](evidence/post-match-v2/README.md) и [протокол](evidence/post-match-v2/verification.json). Локально прошли 118 unit-тестов, 33 combat-теста, 8 benchmark-тестов, design guard и 6 его тестов, lint, typecheck и production build. Browser-проверка завершилась без page errors. Визуальное одобрение владельца остаётся отдельным шагом перед merge.

Во время съёмки внешний CDN иконок был недоступен браузеру: на снимках виден буквенный fallback. URL настоящих иконок сохранены; их доступность на live-странице этой проверкой не подтверждается.
