# Проверка раскладки отчёта — 2026-11-08

Проблема: боковая колонка личного плана занимала всю высоту отчёта. При коротком
плане под челленджем оставалась пустая полоса рядом с графиками. Дополнительный
совет условный: он появляется только при найденном приоритете анализа.

Теперь план находится рядом с итогом и основными показателями; ранний урон, фарм,
покупки и события ниже занимают всю ширину. Соседние карточки показателей имеют
одинаковую высоту, единственная карточка занимает доступную область. Расчёты и
условия появления советов не изменены.

## Проверено

- `npm run lint`, `npm run typecheck`, `npm run build` — успешно.
- `npm run check:design` — правила дизайна и 6 тестов успешно.
- `npm run test:unit` — 233 теста успешно.
- Полный `scripts/verify-post-match-v2.mjs` на production-сборке: 19 групп
  сценариев успешно, ошибок консоли нет. Проверки клавиатуры, фокуса, загрузки,
  ошибок, пустых и частичных данных, сохранения челленджа и обновления отчёта.
- Новая проверка раскладки: 320, 390, 768, 1050, 1051, 1440, 1920, 2560 px;
  короткий и длинный план, раскрытые подробности, один и два показателя.
  Нет горизонтального переполнения и перекрытий, графики занимают всю ширину,
  на мобильном план предшествует показателям.
- Скриншоты просмотрены вручную; полный diff проверен. Изменения ограничены
  раскладкой, документацией и её синтетическими проверками.

Среда: Node 24.22.1, Chromium 153.0.8010.0, Playwright; локальные копии изображений
Steam CDN в тестовом маршруте. Реальные ответы OpenDota/STRATZ и продакшен в этой
UI-проверке не проверялись. Скриншоты не подтверждают достоверность метрик матча.

Воспроизведение после `npm run build`:

```sh
PORT=3096 BASE_URL=http://127.0.0.1:3096 START_SERVER=1 \
  node scripts/verify-post-match-v2.mjs
```

Для среды без системного Chromium скрипт поддерживает `CHROMIUM_MODULE_PATH`,
для локальных копий изображений — `ASSET_DIR`; каталог результата задаётся
через `EVIDENCE_DIR`.
