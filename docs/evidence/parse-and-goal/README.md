# Цель к 10:00 и подробные данные матча

Патч от `main` `98669ecd2754fb7cbc539c3c710d3a297847a7fb` после merge PR #75.
Проверка 2026-11-06. Нового редизайна, изменения оценок или ослабления роли нет.

## Что подтверждено реальными ответами

Оба матча со скриншотов владельца сначала вернули HTTP 200, но
`od_data.has_parsed=false`: без минутных рядов, покупок и результата к 10:00.
Выполнены явные POST `/api/request/{matchId}`. Оба запроса приняты (HTTP 200).
Повторные GET `/api/matches/{matchId}` уже содержат `has_parsed=true` и данные:

| Матч | Герой | Добивания к 10:00 | Цель +5 | Точек золота / опыта | Покупок / отслеживаемых ключевых |
| --- | --- | ---: | ---: | ---: | ---: |
| 9075236042 | Lifestealer | 47 | 52 | 42 / 42 | 36 / 5 |
| 9077889775 | Wraith King | 45 | 50 | 58 / 58 | 44 / 7 |

Сохранённые ответы прогнаны через текущий `normalizeOpenDotaMatch` и выбор результата
к 10:00. Данные не подменялись; сеть constants в этом прогоне отключена, использован
существующий fallback справочников. Проверены наличие рядов после нормализации,
значения среза и цель. Это **не** прогон роль-зависимого endpoint с живым STRATZ.
Сырые payload с аккаунтами не публикуются. Метаданные запросов, время сохранения,
SHA-256 и контрольные числа: [live-data.json](live-data.json).

Первичный контракт OpenDota проверен по закреплённому исходнику
[`svc/api/spec.ts`](https://github.com/odota/core/blob/8d774abda8542390fbd215487d961f1b5c3a3ef3/svc/api/spec.ts):
POST принимает match ID и возвращает `job.jobId`. Исчезновение задания из
[`svc/store/queue.ts`](https://github.com/odota/core/blob/8d774abda8542390fbd215487d961f1b5c3a3ef3/svc/store/queue.ts)
возможно и после исчерпания попыток, поэтому не трактуется как успешный parse.
UI проверяет готовность только повторным обычным анализом. Нет фонового polling,
автоматического повторного POST или новой очереди приложения.

## Что проверено тестами

- Полный STRATZ-ряд дополняет отсутствующий срез; строгая граница `<600`, ноль,
  одновременные события, несовпадение длительности/счётчика, неполный ряд.
- Цель принимается, ожидающий результат дополняется; повтор матча не даёт двойной
  зачёт. Прежняя регрессия #68 с сохранением 3/3 после пустого повтора проходит.
- API обработки: валидация ID, корректный POST, таймаут, лимит 429, некорректное
  тело/ID задания; наружу выходят только контролируемые коды ошибок.
- Очередь ещё не означает готовность; ошибка обновления сохраняет отчёт,
  успешное обновление добавляет ряды. Переключение золото → опыт → золото меняет
  реальные SVG-координаты фикстуры. Только один ряд остаётся видимым без переключателя.
- STRATZ: ответ с подтверждённой ролью после 5 секунд допускается; истечение 12 секунд
  отменяет сетевой запрос и возвращает отдельную ошибку. Все прежние отказы роли сохранены.
- Адаптивность 320/390/768/1440/1920/2560, keyboard/focus, loading/error/empty/partial,
  отсутствие ошибок страницы и горизонтального скролла всей страницы.

## Ограничения и self-review

Живой STRATZ-токен в окружении отсутствует. Не подтверждены свежие ответы роли
для двух матчей, реальная задержка STRATZ и его точный срез к 10:00 для этих матчей.
Подсчёт полного STRATZ-ряда проверен синтетическими регрессиями; это не новая сверка
координат или времени с реплеем. Пограничные события двух провайдеров могут отличаться;
пригодный срез OpenDota сохраняет приоритет. Принятая цель не пересчитывается задним числом.

Полный diff просмотрен: входные данные → нормализация → цель/событие линии → контракт
ответа → UI; состояния очереди/обновления; отмена запроса; устаревшие ответы после
смены игрока/матча. Новые поля необязательны. API-ключи остаются на сервере, raw
ответы и секреты не добавлены. Проверка роли, прежний прогресс, winrates и координатный
слой сохранены; `productReady=false`. Изменение лимита не исправляет неизвестную роль
и не гарантирует доступность STRATZ. PR оставлен владельцу без автоматического merge.
