# Проверка челленджа по новым матчам

Изменение от `main` после PR #89 (`12bfbfe`). Кнопка в принятом челлендже ищет
матчи аккаунта после принятия цели. История OpenDota даёт только кандидатов;
каждый результат проходит существующий `/api/post-match/analyze` с Account ID
и героем. Проверка роли STRATZ, область цели и расчёт добиваний к 10:00 прежние.

## Поведение и ограничения

- Тот же аккаунт, герой, подтверждённый керри, режим и тип лобби. Старые игры,
  исходный матч и игры короче 10 минут не участвуют. Условия проверяются вновь
  по полному разбору; строка истории не подтверждает роль.
- До трёх последовательных разборов за нажатие. Поиск истории ограничен 20 секундами
  на клиенте / 18 на сервере; разборы — общим бюджетом 60 секунд и 40 секундами
  на один ответ, включая чтение тела. Есть остановка и продолжение без сброса.
- История ограничена 300 последними записями; неполная выборка явно обозначается.
  Общая с винрейтом очередь OpenDota и её кеш на 5 минут сохранены. В деталях
  показано время получения истории. Повторный клик не обходит лимиты провайдера.
- Каждый пригодный результат сразу сохраняется. Нет данных — ожидание, не ноль
  и не провал. Ошибка/обрезанный повтор не удаляет подтверждённые значения.
  Пригодное новое число обновляет тот же матч без дубликата. В цикл идут первые
  три проверенных результата по времени матча; позднее подтверждение более раннего
  ожидающего матча может уточнить состав тройки, как и в прежнем ручном потоке.
- Перед записью перечитывается текущая цель. Результат не восстанавливает снятую
  цель и не перезаписывает новый цикл в другой вкладке. Версия localStorage — 1,
  миграции и базы данных нет. Между нажатиями фоновых запросов нет.
- Кнопка проверяет цель в открытом разборе. Автоматическое обновление при открытии
  другого подходящего разбора также сохранено.

## Что проверено реальными ответами

`live-discovery.json` — HTTP 200 нового API с реальной историей аккаунта
116669872, герой 54, режим 22, лобби 7, начиная с 2026-11-02 00:00 UTC.
Найдены кандидаты 9075236042, 9077846847, 9078399043, без обрезания истории.
Отдельный запрос OpenDota вернул 100 строк с нужными полями. Это **проверка поиска**,
а не зачёт этих игр в чей-либо реальный челлендж.

В облачном окружении исходящий Node fetch потребовал `NODE_USE_ENV_PROXY=1`
для штатного прокси; без него запрос завершился ограниченным таймаутом.
Это настройка проверочного процесса, не изменение приложения или TLS.
Некорректный запрос с анонимным Account ID возвращает HTTP 400.

- `typecheck`, `lint`, production `build`, `check:design` — успешно.
- `test:unit`: 244; `test:combat`: 34; `test:benchmarks`: 9;
  `test:stratz-research`: 57; тесты design guard: 6 — без ошибок.
- `check:coordinate-review`: production `/debug/coordinates` остаётся HTTP/RSC 404.
- `scripts/verify-post-match-v2.mjs`: полный прежний набор UI-сценариев прошёл,
  включая PR #68, ручной зачёт при открытии разбора, графики, фильтры и обработку
  парсинга. Для сетевых ограничений браузера использован `ASSET_DIR` с неизменёнными
  изображениями, скачанными с Steam CDN; первый запуск без кеша остановился на
  проверке наличия портрета, а не на сценариях челленджа.
- `scripts/verify-challenge-matches.mjs`: реальная страница, React и localStorage,
  но **синтетические ответы API**. Подробности в `verification.json`.
  Проверены 3/3 при потере данных, числовое исправление, повтор без дубликата,
  ожидание и восстановление, API/закрытая история/ошибка хранилища, отмена,
  смена цели в другой вкладке, reload, клавиатура, ARIA-статусы, ширины
  320/390/768/1440, контролы от 44 px и отсутствие горизонтального переполнения.

Воспроизведение браузерной проверки после `npm run build`:

```sh
START_SERVER=1 node scripts/verify-challenge-matches.mjs
```

Нужен локально доступный Playwright/Chromium. Поддержаны `PLAYWRIGHT_MODULE_PATH`,
`CHROMIUM_MODULE_PATH`, `BASE_URL`, `EVIDENCE_DIR`; production-зависимости не добавлены.

## Что недоступно

В окружении нет `STRATZ_API_TOKEN`. Сквозной зачёт реального нового матча с
подтверждением керри здесь не выполнен. Ошибка настройки проверена синтетически;
роль не подменялась. Для приёмки владельцем: открыть принятую цель, после новой
подходящей игры нажать «Проверить новые матчи» и сверить число к 10:00 с разбором
этого же матча. Матчи, начатые до принятия цели, намеренно не засчитываются.
