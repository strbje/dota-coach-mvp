Основные регрессии:

- Отсутствие токена, отказ авторизации, таймаут, сеть, неправильный JSON/GraphQL, отсутствие роли и несовпадение игрока различаются в реальном пути engine → adapter → проверка роли, с подменённым транспортом. Подтверждённая другая роль по-прежнему блокируется. Повтор с подтверждённым керри проходит. Тело ошибки провайдера и токен не выходят в публичную ошибку.
- График использует существующие интервалы. Полный согласованный поток допускает разбивку по типам; неполный поток не выдаётся за состав полного итога. Пропуск отличается от нуля; короткий конец использует свою длительность и не участвует в выборе снижения.
- Нет добиваний к 10:00 — нет выдуманной цели и инструкций к ней. При доступном отрезке фарма следующий шаг открывает его события. Изменения ограничены представлением и выбором уже подтверждённого эпизода; причины не выводятся из соседства событий.
- #68: повтор без новых добиваний сохраняет 3/3, ожидающая запись дополняется, повторный матч не дублируется. Сохранены изоляция игрока и обработка недоступного хранилища.
- #69: неудачный повтор сохраняет 30/100, время получения, среднее и CSV; успешный повтор обновляет до 40/100. Полнота окон 7/30 не зависит от переключателя среднего.
- В среднем стороны и CSV участвуют пять игроков; выбранный включён ровно один раз. В реестр повторных встреч с другими игроками сам выбранный не попадает.
- После двух загруженных матчей и истечения существующего бюджета 45 секунд третий виден как незагруженный, progress-bar исчезает. Продолжение запрашивает только десять недостающих участников, сохраняя момент расчёта и первые результаты. Отмена/замена не допускают устаревшие ответы.
- Ошибка первого CDN запускает запасной адрес иконки; при отказе всех адресов остаются имя, время и заглушка. Отсутствующие покупки не подменяются выдуманными иконками.
- Сохраняются неизвестные/отрицательные источники золота, неизвестные источники с нулевым балансом и подтверждённые нули. Покрытие золота и опыта по времени независимо.

Пример повторного браузерного прогона после production-сборки:

```bash
START_SERVER=1 EVIDENCE_DIR=/tmp/coach-post-match node scripts/verify-post-match-v2.mjs
START_SERVER=1 EVIDENCE_DIR=/tmp/coach-winrates node scripts/verify-winrates.mjs
```

Нужны Playwright и Chromium; скрипты поддерживают `PLAYWRIGHT_MODULE_PATH`, `CHROMIUM_MODULE_PATH`, `CHROMIUM_EXECUTABLE_PATH`. Необязательный `ASSET_DIR` содержит PNG `items-<key>.png` и `heroes-<key>.png`, скачанные с канонического Steam CDN. Без него используются сетевые изображения. Синтетические данные подключаются только маршрутизацией тестового браузера; production API не получает фикстуры.

## Что подтверждено реальными ответами и первоисточниками

- Steam CDN вернул HTTP 200 и PNG для `dota_react/items/black_king_bar.png` на `cdn.cloudflare.steamstatic.com`, `cdn.steamstatic.com` и `cdn.akamai.steamstatic.com`; старый адрес `items/black_king_bar_lg.png` также ответил. Это проверка доступности адресов в среде разработки, а не воспроизведение ошибки владельца.
- Реальный [`odota/dotaconstants/build/items.json`](https://github.com/odota/dotaconstants/blob/master/build/items.json) содержит относительные пути `/apps/dota2/images/dota_react/items/...` для BKB, Radiance, Armlet и Desolator. Нормализация поддерживает эти пути и допустимые абсолютные адреса без двойного префикса.
- Текущий клиент проекта запрашивает `/benchmarks?hero_id=...`. Первичный код OpenDota: [`benchmarksUtil.ts`](https://github.com/odota/core/blob/8d774abda8542390fbd215487d961f1b5c3a3ef3/svc/util/benchmarksUtil.ts) и [`BenchmarksResponse.ts`](https://github.com/odota/core/blob/8d774abda8542390fbd215487d961f1b5c3a3ef3/svc/api/responses/BenchmarksResponse.ts). Это распределение показателей по герою. Наш запрос не подбирает выборку по рангу, роли, длительности или патчу. Точный состав и размер текущей production-выборки здесь не установлены; UI не называет её личной нормой.

## Что осталось недоступно

Причина отказа разбора **9077889775** в локальной установке владельца не установлена. OpenDota из среды проверки ответил HTTP 403, STRATZ-токена здесь нет. Это ничего не говорит о наличии или корректности токена в `D:\dota-coach`. Исправлена потеря причины ошибки, но успешный реальный разбор этого матча не заявляется. Проверка роли не ослаблена.

Скриншоты владельца не содержат подтверждённых таймингов покупок: по ним нельзя установить, был ли отказ картинки или отсутствовал сам предмет в данных. Запасные адреса проверены отдельно. Исходная зависшая серия не предоставлена реальным ответом/логом; сценарий исчерпания 45-секундного бюджета воспроизведён транспортной фикстурой и теперь явно показан пользователю.
