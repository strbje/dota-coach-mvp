Методика зафиксирована перед реализацией. Экран `/winrates` использует OpenDota и существующие UI-примитивы; отдельного Python-сервиса, БД и фоновой очереди нет.

## Источник и отличия от скрипта

Архив проверен статически, исполняемые файлы и Python не запускались. SHA-256 архива: `4ff11972b5698071e892540895808f6f2fe26ad81c461f047fc53e2bcf79c74f`; `dota_wr.py` (6641 байт): `f3307e872cd8c1b89f354377a279c363220d1d5f7de36f2b3b4bcff33b8008e0`.

Исходник считал 7/30 дней от текущего времени, ограничивал истории последними 300 записями до фильтрации, сохранял кэш без TTL и промежуточные счётчики встреч. Его персональные ID, кэш, архив и Excel в репозиторий не копируются. Тестовые данные синтетические.

## Момент и границы

- Основной режим — «На момент матча»: `asOf = start_time` рассматриваемой игры. Отдельный режим «Сейчас»: `asOf = capturedAt`, единый для всей загрузки. `capturedAt` выдаёт сервер в начале загрузки; продолжение сохраняет этот момент, обновление создаёт новый.
- Окно N дней: начало игры `>= asOf - N * 86400`; её окончание `start_time + duration < asOf`. Нижняя граница включена, верхняя строго исключена. Длительность и результат должны быть известны. Сам рассматриваемый матч исключается в обоих режимах. Даты показываются в `Europe/Moscow` (МСК), вычисления — по timestamp.
- Вход — положительный Match ID или числовой Steam32/account ID (1…4294967294). Steam URL и Steam64 не преобразуются. В режиме одного матча игрок выбирается по слоту, включая анонимного. Без переданного Account ID выбор остаётся пустым; переход из post-match предвыбирает только совпавший аккаунт.
- Ranked (тип лобби 7) и исключение Turbo (режим 23) включены по умолчанию. Эти же фильтры применяются к серии и историям участников. Сам явно запрошенный матч можно открыть независимо от фильтров: они задают выборку его участников.

## Формулы и веса

- `WR = wins / games`, только при `games > 0`. Ноль побед — настоящие 0%; отсутствие игр — отсутствие процента.
- Победа: `radiant_win === (player_slot < 128)`, только для известных результата и игрового слота. Отсутствующий результат не является поражением.
- Среднее стороны — арифметическое среднее доступных процентов участников с равными весами. Выбранный игрок исключён: ожидаются 4 союзника и 5 соперников, включая места без доступного ID. Покрытие рядом со средним — число участников с процентом, а полнота их историй показывается отдельно.
- 1/1 и 50/100 дают **75%**, а не 51/101. Объединённая доля побед здесь не используется. Разница «союзники минус соперники» выражена в процентных пунктах.
- В серии сначала вычисляются стороны каждого матча. Сводка использует только матчи, где есть обе стороны, с равным весом каждого такого матча; число пар показано. Повторный участник учитывается в каждой встрече. Отдельная таблица уникальных игроков показывает окончательные числа встреч вместе/против и Match ID; проценты из разных моментов в один «процент уникального игрока» не смешиваются.
- Ключ встречи — Match ID + слот. Личные матчи дедуплицируются по Match ID. Дублированные слоты/аккаунты в составе считаются недостоверными; неоднозначные исторические записи исключаются. Итоговые счётчики вычисляются по всему доступному составу серии до загрузки процентов.

## Полнота и состояния

История запрашивается страницами по 100 с сортировкой по времени начала, максимум 3 страницы / 300 записей. Пагинация останавливается на границе окна, исчерпании ответа либо бюджете. Лимит 300 не доказывает полноту 30 дней. Для каждого окна сохраняются число побед/игр, первая и последняя подходящие игры, достигнутая граница истории и причина ограничения. Пропущенные/повреждённые записи и ошибки следующих страниц не скрываются. Полное окно означает только полноту доступной истории OpenDota, а не гарантию, что провайдер знает каждую игру.

Анонимный участник, ограниченная провайдером история, пустая доступная история, неопределённая доступность и ошибка провайдера — разные состояния. Пустой ответ без подтверждения доступности не объявляется закрытым или полным. История с подходящими играми и ограниченным покрытием даёт процент с пометкой неполной выборки. Никаких подстановок 0% или 50%.

## Загрузка, кэш и отмена

Первая серия ограничена тремя последними подходящими матчами за 7/10/30 дней; найденное количество и ограничение видны. Кнопка следующих трёх матчей продолжает зафиксированный список Match ID и сохраняет `capturedAt`; составы с ошибкой можно повторить отдельно. Проверяется принадлежность выбранного игрока и соответствие каждого добавляемого матча периоду/режимам. Составы и истории не собираются одним многоминутным запросом. План/партия составов ограничены 18 секундами, отдельный участник — 14 секундами; клиент получает результаты постепенно двумя запросами одновременно и делает паузу через 45 секунд. Продолжение/повтор доступны явно. Обновление, смена игрока или фильтров отменяют клиентские запросы и меняют поколение загрузки, поэтому старый ответ не попадёт в новую группу.

Общий для процесса шлюз OpenDota: не более двух одновременных запросов, интервал запуска 1100 мс, таймаут запроса 8 секунд, максимум один повтор сетевой ошибки/5xx в оставшемся бюджете. На 429 соблюдается `Retry-After` (по умолчанию 60 секунд); длинного ожидания внутри HTTP нет. Кэш в памяти ограничен по размеру, TTL 5 минут; одинаковые запросы дедуплицируются. Отмена одного подписчика не ломает общий запрос другого; уже начатый запрос завершается в своём ограниченном бюджете. Ограничение действует на процесс, не является распределённым лимитером.

Кэш исходных ресурсов учитывает путь, игрока, сортировку, страницу и фильтры. Ключ вычисленного результата дополнительно включает Match ID, игрока, 7/30 дней, фильтры, режим и точный `asOf`; исторические и текущие результаты разделены. В результате видны время получения самых ранних использованных данных, время расчёта и истечение кэша. Закрытые/ошибочные/ограниченные результаты не сохраняются в кэш расчётов; успешные исходные ответы живут не более TTL. Кэш теряется при рестарте и не сохраняется в браузере.

## Представление и экспорт

Вверху — средние, разница и покрытие; ниже — составы с раскрываемыми выборками 7/30 дней, серия и уникальные участники. Сортировка меняет порядок строк, не веса. CSV экспортирует текущий результат и текущую сортировку, включает недоступные/ожидающие строки и причины, фильтры, оба окна, выборки, итоговые счётчики и моменты расчёта. UTF-8 BOM, разделитель `;`, CRLF, экранирование кавычек и формул поддерживают открытие в Excel без новой зависимости.

Средние описывают наблюдаемую историю участников. Это не вероятность победы команды, причина поражения и не оценка качества матчмейкинга.

## Контракт OpenDota

Используются `/matches/{id}`, `/players/{id}`, `/players/{id}/matches?sort=start_time&significant=0&limit=100&offset=…`. Фильтры повторно проверяются локально; `date` не используется, поскольку привязан к текущему времени провайдера. Контракт проверен по [официальному исходнику OpenDota](https://github.com/odota/core/tree/271b0dd914d029acf9a0241499dc826f87d243cc): `svc/api/requests/playerParams.ts`, `svc/util/buildPlayer.ts`, `svc/api/api.ts`, `svc/api/responses/PlayerObjectResponse.ts`. Пустая история может быть следствием приватности, а не отсутствия матчей. `profile.fh_unavailable` означает неудачное обновление истории; API использует этот флаг как ограничение доступа (с исключением профессиональных игроков). UI пишет «История ограничена OpenDota», а не утверждает, что пользователь точно закрыл Steam-профиль. Без подтверждения доступности пустой ответ не получает пометку полного окна.

Результаты проверок и изображения публикуются отдельно в `docs/verification/winrates/`; синтетическая проверка интерфейса отделяется от живых запросов.
