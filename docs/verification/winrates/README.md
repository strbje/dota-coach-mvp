## Интерфейс — синтетические данные

`scripts/verify-winrates.mjs` проверяет production build с подменёнными ответами API, построенными из маленьких обезличенных fixtures. Playwright и Chromium нужны только в окружении проверки, в production-зависимости они не добавлены.

```sh
npm run build
START_SERVER=1 node scripts/verify-winrates.mjs
```

При внешней установке Playwright/Chromium можно задать `PLAYWRIGHT_MODULE_PATH`, `CHROMIUM_MODULE_PATH` и `CHROMIUM_EXECUTABLE_PATH`. `BASE_URL` позволяет использовать уже запущенный сервер, `EVIDENCE_DIR` — другой каталог результатов.

Проверены ширины 320, 390, 768, 1440, 1920; выбор Radiant/Dire, исключение выбранного игрока, раскрытие выборок, клавиатура и focus, сохранение единого момента «Сейчас», отмена/замена запроса, частичные/пустые/ошибочные данные, продолжение серии, итоговые счётчики уникальных игроков, CSV и переход с предвыбранным аккаунтом. Протокол: [verification.json](verification.json).

Повторная проверка выявила автоматический выбор первого анонимного участника при отсутствующем Account ID. Браузерная регрессия сначала воспроизвела ошибку: выбран слот `1` вместо пустого значения. После исправления выбор остаётся пустым и запросы историй не начинаются до действия пользователя; предвыбор совпавшего аккаунта из post-match по-прежнему проходит. Production-сборка и весь сценарий браузерной проверки повторно прошли.

## Отдельная живая проверка OpenDota

См. [live.json](live.json): запрос выполнен 23.10.2026 в 13:38 UTC через реальные API страницы (`plan`, затем один `participant`), без подмены ответов. Контрольный Match ID `8781054570` относится к апрелю 2026, а не к дате проверки. Профили/имена/Account ID участников и пользовательский архив в доказательства не включены.

Получены HTTP 200, состав из 10 мест и 300 исторических записей одного доступного участника. Самая старая из этих записей оказалась позже контрольной игры: оба окна честно помечены `complete: false`, `limitedBy: cap`, `rate: null`. Поздние игры не попали в исторический процент. Это подтверждает рабочий запрос и обработку недостаточного покрытия; успешный полный исторический расчёт для девяти реальных участников этой проверкой не подтверждён.

Для повторного живого запроса задайте `LIVE_MATCH_ID` при запуске скрипта. Он делает ограниченную проверку одного участника после синтетической проверки UI и сохраняет отдельный файл; синтетические скриншоты не выдаются за live-данные.
