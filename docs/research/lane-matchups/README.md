Вычитание 0:00 убирает значение счётчика на старте; нельзя считать отсутствующий старт нулём. Описание контракта не гарантирует совпадения с суммой combat log по округлённым секундам.

«Получено» — сумма событий по тому же окну/фильтрам, **не потерянное здоровье и не STRATZ `heroDamageReceivedPerMinute`**. Лечение, восстановление, затраты здоровья и расходники здесь не вычитаются. Проверены 11 границ `0,60,…,600` в каждом матче. В локальном потоке нет дубликатов этих секунд. Совпали **30 из 33** значений; три несовпадения ниже сохранены в артефакте.

### Ротации и время на линии

Полная метка `lane` теряет порядок перемещений. В pinned OpenDota она выводится по преобладающей области в `lane_pos`; `is_roaming` использует долю наиболее частой области, а не журнал телепортов или уходов.

Для диагностики сохранены раздельные счётчики **живых позиционных семплов** 0–5 / 5–10 для всех игроков по старым прямоугольным областям OpenDota. В каждом окне есть 300 секундных семплов. Мёртвые состояния и координаты вне областей выделены отдельно. Это воспроизведение классификатора источника, **не валидация актуальной геометрии карты и не точное «время на линии»**; координаты в продукт не переносятся.

- `9003795847`: WK и Oracle в первой пятиминутке имеют 283 и 294 живых семпла нижней области; Axe/Techies — 276/260. Это кандидат обычной 2v2 для начала матча. После 5:00 у Oracle только 151 такой семпл, появляются другие области. Нельзя объявлять всю десятую минуту неизменной 2v2.
- `9078566584`: Omniknight имеет 295 семплов нижней области до 5:00; после 5:00 появляются 82 верхних. Реальные события урона WK по нему — **8:10–9:56**. Это подтверждает встречу с третьим противником; смена области согласуется с ротацией, но не доказывает её причину или длительность 3v2.
- `9019592113`: урон WK по Crystal Maiden — **6:40–8:20**, по Dragon Knight — **9:53–9:59** внутри `[0,600)`. Их исходные метки — нижняя и средняя линии. Нужен контекст ротаций, даже если исходная верхняя пара определена правильно.

**Не закрытый сценарий приёмки:** в этих примерах не подтверждена сложная линия с ранним уходом керри в лес. Нельзя объявить линию сложной из-за поражения, низкого урона или краткого захода в лес. Нужен ещё один матч с известным эпизодом ухода; текущие три не заменяют этот контроль. Визуального просмотра в клиенте Dota в этом исследовании не было.

### Что означает STRATZ LaneScore

Официальная [knowledge-base #39](https://github.com/STRATZ-Esports/knowledge-base/issues/39), обновлена **21.07.2023**, описывает собственный результат линии:

`LaneScore = AdjustedLaneNW + LaneXP + LaneCS + AdjustedLaneKDA / 2`.

Это нормированные командные различия с внутренними поправками и порогами по линии/рангу, а не индивидуальный индекс агрессии. В описании использованы 10 минут (Turbo — 7); **CS скелетов WK исключаются**. Некоторые поправки не раскрыты полностью. Поэтому одинаковые цифры CS у нашего счётчика и LaneScore не ожидаются автоматически, а историческое исключение нельзя без свежей проверки переносить на другие поля STRATZ. Число максимальных крипов из старого описания не переносим на текущий патч.

Самостоятельная реализация этого закрытого набора поправок по краткому описанию не даст эквивалентный результат. IMP также не является доступной rule-based методологией: официальное [описание #23](https://github.com/STRATZ-Esports/knowledge-base/issues/23) сообщает о внутренней модели.

## Методология следующего шага — предложение, не готовая оценка

1. **Контекст:** отдельные 0–5 и 5–10, CS/denies, заработанное золото/XP и net worth как разные метрики, смерти, нанесённый и полученный hero-owned damage, исходные пары и подтверждённые изменения состава. Не пересчитывать сумму урона в «давление» и не вычитать полученный урон для универсального индекса.
2. **Группа:** тот же герой **и подтверждённая позиция**, патч, режим, сопоставимый ранг; для 2v2 — союзник и оба противника с ролями. Не смешивать 1v1 винрейты в воображаемую вероятность 2v2. Не подменять неизвестную роль `lane_role`. Не склеивать периоды по календарной неделе через патч.
3. **Распределение:** если доступны индивидуальные наблюдения или проверенные квантили — показать медиану, межквартильный интервал, N и долю пропущенных матчей. По одному среднему и N нельзя восстановить распределение, медиану или процентиль.
4. **Точность:** заранее выбрать допустимую ширину интервала для конкретной пользовательской задачи и проверить её на пилоте. Для повторных наблюдений учитывать зависимость игроков/матчей; для долей определить знаменатель, ничьи и пересечение stomp/win counts. Только после этого выбирать N. Универсальный порог вроде «30 матчей достаточно» не вводится.
5. **Редкая группа:** «Недостаточно матчей с таким составом для сравнения». Более широкую группу можно показывать только отдельно и с явным изменением условий, не скрытой подстановкой и не как прогноз исхода.
6. **Польза игроку:** факт + контекст + конкретный эпизод для проверки. Например, «В 8:10–9:56 ты также наносил урон Omniknight; проверь этот отрезок отдельно от начала линии». Это не доказательство ошибки или успешной агрессии. Продуктовую формулировку/оценку согласовать отдельной задачей.
