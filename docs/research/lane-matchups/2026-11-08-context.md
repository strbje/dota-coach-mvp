**Вывод:** смерть и последующие нейтралы сами по себе не доказывают отказ от линии
или проигранный матчап. Этот кандидат не закрывает положительный контроль
«тяжёлая линия → ранний устойчивый уход в лес». События не говорят, почему игрок
сменил цель; нейтралы могут быть рядом с линией или отведены к ней. Старые
прямоугольные области OpenDota тоже не заменяют проверку фактического поведения.
Тип крипа в этой таблице не доказывает точное место добивания.

Не вводим правило «нейтралы после смерти = проиграл линию». Не назначаем порог
секунд отсутствия на линии без размеченного контроля и проверки ротаций,
смерти/возрождения, пулла и повторного возвращения к волне.

## Почему текущая выборка не даёт оценку двух пар

Основание — авторизованная schema и реальные ответы владельца от 07.11,
не предположение по названию endpoint. [Извлечённый контракт](cohort-contract-2026-11-08.json)
содержит типы аргументов и SHA исходного файла.

| Поле STRATZ | Доступно в полученном контракте | Чего не хватает для задачи |
|---|---|---|
| `heroStats.laneOutcome` | Один герой, союзник/соперник, week, position, bracket; строки `heroId1/heroId2` и counts | Оба союзника и оба противника в одной группе, ID исходных матчей, явные фильтры патча/режима, распределение урона |
| `heroStats.stats` | Герои, week, position/bracket, границы времени, группировка | Нет аргументов союзной/вражеской пары или явного патча/режима; определение возвращаемого типа ещё не выгружено |
| `matchUp`, `heroVsHeroMatchup` | Герой/герои, week, bracket и пагинация | Не заявляют группу линии 2v2; нет фильтров позиции и длительности нахождения на линии |
| `guide` | Герой, один союзник, один соперник, position, isPro | Нет второго соперника и полной группы; список гайдов не равен репрезентативной статистике линии |
| `winGameVersion` | Результаты по версиям, роли, рангу, режиму | Результат матча, не ранняя линия или нужная совместная группа |

В реальном ответе для WK: с Oracle — `N=55`, против Night Stalker — `N=200`,
против Winter Wyvern — `N=27`. Это **три отдельные попарные строки**, не N матчей
`WK + Oracle против NS + WW`. Их нельзя складывать, усреднять их доли побед или
считать минимум 27 размером пересечения: общих match IDs нет, пересечение неизвестно.
Дополнительно остаются подтверждённые несовпадения меток роли/ранга из предыдущего отчёта.

**Установлено:** эти ответы не дают пригодную совместную выборку.
**Не установлено:** что такой возможности вообще нет во всём API STRATZ.
Прежняя выгрузка не включала корневые запросы, определения всех фильтров и
возвращаемый тип `stats`. Именно этот пробел закрывает новый минимальный сбор схемы.

## Следующая проверка API: только метаданные

Добавлен `--cohort-schema-only` в существующий исследовательский CLI:

- Не требует Match ID; не запрашивает матчи, аккаунты, историю или новые агрегаты.
- Читает настоящий query root и определения относящихся к задаче типов/фильтров.
  Не предполагает имя корневого типа.
- До **трёх HTTP-запросов**, максимум 24 типа в каждом дополнительном запросе.
  Непросмотренные зависимости сохраняются в `unfetchedTypes`; их отсутствие
  в выгрузке не трактуется как отсутствие возможностей API.
- Ошибки HTTP/GraphQL, null-типы и отсутствующий root остаются `partial`; повторов
  нет. Сохраняются rate-limit headers. Успешная schema не означает валидную выборку.
- Токен читается из существующего локального окружения; готовый файл не перезаписывается.

Также исправлено подтверждённое имя поля в **исследовательском** allowlist:
`deniesPerMinute` вместо несуществующего в полученной schema `denyCountPerMinute`.
Старые выгрузки не переписываются; отсутствие денаев в них не превращается в ноль.
Продуктовый normalizer не затронут.

Здесь токен STRATZ не настроен, поэтому новый режим проверен mock-ответами,
а его реальный авторизованный запуск остаётся на стороне владельца. Это не
повод ослаблять проверку роли или объявлять все capabilities API недоступными.

Команда для текущего исследовательского PR:

```powershell
cd D:\dota-coach

git pull --ff-only
$out = Join-Path $env:TEMP ("dota81-cohort-schema-" + (Get-Date -Format "yyyyMMdd-HHmmss") + ".json")
node scripts/probe-stratz-lanes.mjs --cohort-schema-only "--out=$out"

```

После слияния PR использовать `git switch main`. Прислать только JSON,
не токен и не `.env`. Повторно отправлять два прежних больших JSON и реплеи не нужно.

## Остаток и решение для MVP

1. Нужен **один Match ID, герой и примерная минута**, когда керри действительно
   надолго оставил тяжёлую линию и начал фармить лес. По возможности достаточно
   известного владельцу эпизода; ещё один большой файл заранее не требуется.
   Проверить смену занятия и возвраты к волне; причину ухода не выводить только из цифр.
2. По новой schema проверить, доступен ли ограниченный источник **совместных**
   матчей с обеими парами и нужными условиями. Если да — проверить реальные rows,
   фильтры, дубликаты и происхождение N; если нет — зафиксировать ограничение,
   не строить собственную массовую инфраструктуру для MVP.
3. Для сопоставимой группы нужны роли всех участников, патч, режим, рейтинг,
   период и покрытие раннего окна. Распределения урона/фарм/опыт/смерти анализировать
   совместно; порог N выбирать по точности конкретной выборки, а не объявлять
   произвольное число достаточным. При неполных условиях показывать факт и ограничение.

Данные нового реплея усиливают проверку ограничений, но не закрывают #81.
Оценка сложности/агрессии не включается. Production и визуальный просмотр
в клиенте Dota этим этапом не проверены; #50 также остаётся открытой.
