# #50 — служебный просмотр двух реальных матчей

Продолжение [числовой сверки](2026-11-04.md) в PR #73. Владелец подтвердил:
**добивания скелетами WK относятся к фарму игрока**. Они не исключаются из итогов.
Нормализатор, adapter, порог 5s, `productReady=false` и `structural_only` сохранены.

## Что добавлено

`/debug/coordinates` доступен только при `npm run dev`. В production маршрут
возвращает 404 до чтения набора; query-параметры не включают его. В навигации продукта
ссылки нет. Экран читает компактный локальный [набор](visual-review-data.json),
не делает запросов к STRATZ/OpenDota и не требует токена.

```powershell
cd D:\dota-coach
git fetch origin
git switch research/stratz-coordinates-50
git pull --ff-only
npm ci
npm run dev
```

Открыть `http://localhost:3000/debug/coordinates`. Если checkout содержит свои
незакоммиченные изменения, сначала сохранить их обычным способом; команды не
предлагают `reset`, `clean` или принудительное переключение.

В экране есть:

- два матча, периоды, исходные категории STRATZ и исполнитель по боевому журналу;
- все CS, включая одинаковые секунды, отсутствие координат и события без категории;
- все 9 смертей: начало ячейки adapter, собственные XY события и реальная позиция
  первого dying-state; одна непривязанная смерть остаётся без точки adapter;
- фонтаны, T2 и два положения появления Рошана; точные значения в таблицах;
- локальное PNG/JPEG/WebP для ручного наложения, без отправки файла и сохранения.
  Загрузка **не подтверждает** версию изображения, crop или калибровку.

Схема — декартова плоскость с одинаковым масштабом обеих осей, X вправо, Y вверх.
Рамка взята из camera bounds реплеев. Это не изображение местности и не проверенный
crop миникарты. Точки на screenshots получены из реальных файлов; схема не содержит
синтетических игровых координат. По ней нельзя судить о проходимости, обзоре и зонах.

## Дополнительно подтверждено реальными данными

Все CS сопоставлены с **первым увеличением** счётчика `lastHits` в combat death
WK/его скелета. Проверены последовательность `1..N`, равенство числа CS итоговому
`numLastHits`, время каждого соответствия в ±2s. XY не участвует в подборе.
Повторные строки с тем же counter не создают ещё одно добивание.

| Матч | Все CS | Сам герой | Скелеты WK | Пригодные XY | Без полной пары | Без категории STRATZ |
|---|---:|---:|---:|---:|---:|---:|
| 9019592113 | 302 | 247 | 55 | 301 | 1 | 44 |
| 9003795847 | 281 | 213 | 68 | 270 | 11 | 33 |

Все **123** добивания скелетами включены в **583** события. Фильтр меняет просмотр,
а не принадлежность добивания игроку. Флаги STRATZ сохранены: например, среди
неразмеченных событий первого матча есть разные frog NPC, Roshan и T2; во втором
также imps, скелеты Clinkz, sentry и здания. Отсутствующий флаг не заменён догадкой.

Для ранее выбранных 13 эпизодов добавлены ближайший снимок WK и **все** погибающие
сущности в ±0.1s от combat time. В ряде окон несколько кандидатов: например, при
CS index 236 второго матча их шесть. Это не доказанная привязка жертвы по handle.
Квадраты подписаны кандидатами; raw XY не подменяются положением героя или сущности.
**Кому принадлежит CS XY и с каким временным смещением, пока не установлено.**

Это проверка записей архивного каталога. Самих material/texture/overview bytes

и `steam.inf`. Текущий клиент может иметь другой CRC — это будет зафиксировано,
а не принято за исторический эталон. Старые JSON/реплеи повторно не нужны.

## Как воспроизвести набор и что проверить визуально

Порядок декодирования и SHA исходников сохранены в [replay/README.md](replay/README.md).
[build_visual_review.py](replay/build_visual_review.py) проверяет capture/decode hashes
и complete footer, отказывается перезаписывать результат. `source.builderSha256`
связывает набор с точным исходником. Полные исходные ответы и JSONL не входят в PR.

После получения правильного asset/crop нужны минимум:

1. Фонтаны обеих сторон, Radiant T2 bot, Dire T2 top, два положения Рошана:
   сверить ориентацию, масштаб и смещение по независимым неколлинеарным ориентирам.
2. Смерти 9019592113 в 14:50, 19:05 и 33:39; 9003795847 в 2:22:
   сверить игровой таймер, начало смерти и положение героя. `exact` по целой секунде
   не считать пространственной гарантией; 19:05 не заполнять из позиции за 12s.
3. CS 9019592113 №246 (29:40, скелет) и 9003795847 №91 (13:25), №177/178
   (19:01, скелет и герой): определить фактического атакующего, жертву и момент.
   Одинаковая секунда не означает дубль. Время combat может отличаться от целой
   секунды API; его дробное значение есть в карточке.

Если Dota-клиент не открывает эти версии реплеев, достаточно сначала четырёх
asset-файлов. Скриншоты/клипы нужны только для оставшейся клиентской проверки:
полная миникарта, Match ID, WK и игровые часы должны быть видны.

## Границы проверки

Проверка экрана в Chromium 134 (Playwright 1.51.1): ширины 320, 390, 768 и 1440px
без горизонтального переполнения страницы, включая открытые таблицы/источники.
Проверены фильтры обоих матчей, сохранение 55/68 добиваний скелетами, две записи
в 19:01, пустой/неверный период, непривязанная смерть, ориентиры, загрузка локального
изображения и сохранение предыдущей подложки при ошибке. Внешних запросов экран не
отправил. Labels, Tab/Enter/Space, видимый фокус и `aria-pressed` проверены; loading
status проверен в серверном HTML-потоке. Временная пустая/повреждённая fixture
проверила empty/error и успешную повторную загрузку; исходный файл восстановлен.

Screenshots текущего экрана, **реальные STRATZ/replay данные, без подложки**:
[desktop 1440](screenshots/coordinates-desktop-1440.png),
[mobile 390](screenshots/coordinates-mobile-390.png),
[смерти, desktop 1440](screenshots/coordinates-deaths-desktop-1440.png).
Это доказательство рендера служебной схемы, не клиентский кадр Dota 2.

Восемь новых unit-регрессий проверяют сохранность набора, фильтры, одинаковые секунды,
null/zero/invalid XY, непривязанную смерть, геометрию схемы, dev-only gate и повреждённый
формат. Повтор builder дал побайтово идентичную fixture; дополнительно проверены отказы
перезаписать файл, принять другой capture hash и работать с отключёнными assertions.

Production build проверен отдельным HTTP smoke test (`npm run check:coordinate-review`,
добавлен в CI после build): главная — 200, исследовательский URL и query bypass — 404,
Flight/RSC — служебный HTTP 200 с `NEXT_HTTP_ERROR_FALLBACK;404`, без данных fixture.
Дополнительно локально эти запросы прошли при временно отсутствующей fixture: gate
срабатывает до чтения файла. Синхронная проверка стоит перед loading boundary.

Реальные файлы подтверждают счётчики, исполнителей и измеренные позиции; тесты
сохраняют эти данные при фильтрации и рендере. Синтетические случаи проверяют null,
нулевую координату, неверные bounds/формат, пустое и ошибочное состояния, загрузку
картинки. Они не подтверждают реальные координаты или map projection.

Код отделён от продуктового анализа. Полный diff сохраняет исправления #68/#69/#71/#72;
ни один результат не даёт разрешения на публичную карту или координатную оценку.
Результаты команд, browser-проверок и CI конкретного head приведены в PR #73.
Issue остаётся открытой; решение о следующем продуктовом этапе принимает владелец.
