# #50 — проверка полученного архива map assets

**Архив полный и исправный, но ранее запрошенный список файлов оказался недостаточным.**
`dota.vmat_c` ссылается на **`materials/overviews/dota_tga_d8178876.vtex`**, которого
нет в архиве. Две запрошенные PSD-текстуры успешно декодированы, однако ни одна
не является этой зависимостью. Подмена текстуры по похожему имени не выполнена.
Это неточность нашего первоначального списка, а не ошибка выгрузки владельца.

Продолжение [числовой сверки](2026-11-04.md) и [служебного просмотра](2026-11-04-visual.md)
в том же PR #73. [Машинный протокол](observations-map-assets-2026-11-04.json) хранит
хеши, реальные параметры и недостающую зависимость. `productReady=false` и
`structural_only` сохранены; изменения продуктового кода и служебного экрана не нужны.


Та же ссылка есть в RERL, child resource list и searchable user data. В обоих
исторических VPK manifests файл **`dota_tga_d8178876.vtex_c`** присутствует:
**1 050 660 байт**, CRC32 **`d9e2fc78`**. Его bytes недоступны; эта цепочка пока не замкнута.
`simple_material` также указан отдельно, но его ветка не проверялась. Нельзя утверждать,
что клиент выбранного реплея использует именно default material, simple material
или эту статическую подложку: фактический клиентский рендер ещё не просмотрен.

## Декодирование и первоисточники

Использован [Source 2 Viewer CLI 20.1](https://github.com/ValveResourceFormat/ValveResourceFormat/releases/tag/20.1),
фактическая версия `20.1.7467+9e2e6c7f67e3c4e5a5f443a60c3a5d841ba8f304`.
Linux-архив проверен по SHA-256
`29d25a6d6b62377fc5386c3e5145b0a2180a401a50041afe9494b3f503deaef5`.
Команды `--all` прочитали material/RERL/texture metadata; `--output` декодировал
обе имеющиеся текстуры в PNG. Их реальные изображения просмотрены. Декодированные
RGBA-массивы различаются в 2612 пикселях (максимальная разница канала 42), поэтому
они не считаются побайтово одинаковыми. Ни одна не принята за referenced texture.

Воспроизведение после извлечения ZIP с заменой Windows `\` в путях на `/`:

```bash
./Source2Viewer-CLI --input assets/materials/overviews/dota.vmat_c --all
./Source2Viewer-CLI --input assets/materials/overviews/dota_psd.vtex_c --all
./Source2Viewer-CLI --input assets/materials/overviews/dota_psd.vtex_c --output decoded/
./Source2Viewer-CLI --input assets/materials/overviews/dota_psd_8b4a9409.vtex_c --output decoded/
```

Выходные имена PNG определяются texture exporter; сверять их с выводом CLI, а не
предполагать переименование по имени аргумента `--output`.

Дополнительно прочитан первоисточник Valve
[Source SDK MapOverview.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/019e91ccd650a34745934c65cdbbe89ffcc44ede/src/game/client/game_controls/MapOverview.cpp)
и [mapoverview.h](https://github.com/ValveSoftware/source-sdk-2013/blob/019e91ccd650a34745934c65cdbbe89ffcc44ede/src/game/client/game_controls/mapoverview.h):
там `WorldToMap` вычитает origin, делит X на scale, Y на отрицательный scale;
логическая область имеет размер 1024. **Это реализация Source SDK, не исходник
рендера Dota 2**, поэтому её перенос остаётся гипотезой. Valve Wiki о minimap/
overview недоступна (ошибка получения/403); вторичные пересказы не заменили проверку.

При этой гипотезе полученный overview дал бы область `[-9472,9472]` по обеим осям
и преобразование `px=(worldX+9472)/18.5`, `py=(9472-worldY)/18.5` в логические
координаты 1024×1024. Физическое изображение материала заявлено как 512×512.
Эта условная формула **не применена** к приложению и не объявлена подтверждённым crop.
Camera bounds старой служебной схемы — отдельные данные; приравнивать их к overview нельзя.

## Что осталось и следующий минимальный вход

1. Получить **только** `materials/overviews/dota_tga_d8178876.vtex_c`. Исправленная
   [PowerShell-инструкция](map-assets.md) использует уже скачанный CLI, не требует
   токена и собирает один небольшой ZIP. Повторять предыдущую выгрузку не нужно.
2. Проверить CRC/размер, декодировать фактически referenced texture, затем проверить
   на ней фонтаны, T2 и положения Рошана без подгонки масштаба по отдельной точке.
3. Сверить реальный рендер/настройку миникарты и контрольные эпизоды клиента из
   [визуального протокола](2026-11-04-visual.md#как-воспроизвести-набор-и-что-проверить-визуально).
   Даже совпавшая подложка не подтверждает время CS, координату атакующего/жертвы
   или допустимую погрешность смерти.

Это проверка реального архива и первоисточников, не синтетический тест координат.
Изменения этого этапа — только документация/наблюдения. Служебный экран, итоговые
583 CS (включая 123 добивания скелетами), расчёты и все ограничения PR #73 сохранены.
Issue #50 остаётся открытой, PR не мержится автоматически.
