### Проверяемые гипотезы

| Гипотеза | Вердикт сейчас | Недостающее доказательство |
|---|---|---|
| X/Y — полные finite-пары сетки 0..255 | Структурное допущение текущего normalizer; реальная выборка отсутствует | Все пары выбранных игроков, диапазоны, дробные значения, null/пропуски |
| `mapX=X/255`, `mapY=Y/255` правильно размещают точки на карте | Недостаточно данных | Ориентация и crop карты соответствующего build; минимум три неколлинеарных ориентира |
| `world=(raw-128)*128` даёт игровую позицию | Недостаточно данных | World position из того же replay; offset, размер ячейки, vec/округление и центр против угла |
| Ближайший sample в ±5s соответствует смерти | Недостаточно данных | Синхронные death/position/replay часы, кадры до/в/после смерти; телепорт, respawn и Reincarnation отдельно |
| Все CS подходят для farm heatmap героя | Не подтверждено; есть 77 неразмеченных событий | Собственная позиция против event-owned position, summoned/illusion kills, категории NPC и пропуски |
| Все goldEvents — фарм | Не подтверждено; реальные goldEvents не получены | Значение/знак/reason и контроль creep/hero/objective/passive/loss; не переносить OpenDota gold enum автоматически |
| isRadiant на objective — команда, получившая награду | Не подтверждено | Сверить принадлежность объекта, убийцы и награды по одному событию |

Шаг 128 в parser делает гипотезу правдоподобной, но не подтверждает offset `-128` или
отсутствие внутриклеточной части. Совпадение времён не является пространственной
погрешностью: за пять секунд герой может переместиться, а телепорт нарушает любую
линейную интерполяцию. Confidence `exact/high/medium/low` текущего adapter отражает
только временной delta, не точность места смерти.

Гистограммы OpenDota сохранены как исходные ключи без объявления их STRATZ-координатами.
Исходные STRATZ X/Y, преобразованные значения и расхождения для всех строк пока
**недоступны**; заполнять их правдоподобными числами нельзя.

Для CS достаточно коротких эпизодов: у 9019592113 — **0:56** (`isCreep`), **2:44**
(`isNeutral`), **23:46** (`isAncient`), **11:16** (все false); у 9003795847 — **0:58**,
**8:58**, **19:01**, **2:01** соответственно. Сверить NPC, фактического атакующего,
его положение и позицию события, суммарные LH до/после. Для gold после выгрузки выбрать
события с разными реально возвращёнными reason/знаками; сейчас их таймкоды неизвестны.

Для каждого проверенного события записать одну строку:

`matchId / heroId / slot / map build + hash map asset / replay SHA-256 / event path
и индекс / raw time,X,Y / выбранный position index,time / signed deltaSeconds /
ожидаемая точка и источник (кадр или parser entity) / mapX,mapY,worldX,worldY из
существующего normalizer / dx,dy и единицы / погрешность эталона / вердикт`.

1. Проверить часы по нескольким смертям/объектам и паузе, если она была. Записать
   game start; не считать `tick/30` безусловным игровым временем. Отрицательные времена
   сохранить. Не выравнивать провайдеры молча.
2. Проверить все четыре квадранта и обе оси на неколлинеарных ориентирах. World-остаток
   измерять только при независимом числовом эталоне. По кадру допустим визуальный вывод
   об ориентире, но нельзя изобретать точную погрешность в world units.
3. Для смерти показать nearest sample и обе соседние точки, включая signed delta и
   все одинаково близкие кандидаты. Текущий adapter при равном delta сохраняет порядок
   входного массива; это не доказательство предпочтительности точки после смерти.
4. Отдельно посчитать raw records, полные finite-пары, пары 0..255, usable **timed** пары,
   неполные/нечисловые/вне диапазона, промежутки и unmatched events. `(0,0)` с двумя
   числами не путать с отсутствием пары; отсутствующие значения не дополнять нулями.
5. Для всех смертей сохранить связь или явный unmatched; 0–5s только временной порог.
   Проверить resurrections, respawn и телепорты без причинных выводов.
6. Для CS/gold отдельно установить значение координаты и покрытие. При разногласии
   источников не выбирать удобный поток. Даже положительный результат не разрешает
   оценки про вижен, «плохую зону» или расстояние до команды.

## Минимальная локальная выгрузка

Добавлен только самостоятельный `scripts/probe-stratz-coordinates.mjs`. Необходимость
подтверждена кодом: существующий debug route выбирает hero 54 и отдаёт лишь первые/последние
пять позиций и пять research samples; прежний cohort probe не запрашивает координаты.
Нормализатор, adapter и приложение не изменены и не продублированы.

Скрипт сначала получает актуальную schema с описаниями, затем выбирает подтверждённые
scalar/enum поля position/death/CS/gold и building/Roshan streams. Сохраняет time, значения,
event-owned координаты и enum descriptions без предположений об их смысле. Null, отсутствующий
поток, пустой массив, неполная пара и одинаковые события не объединяются. Экспорт содержит
только выбранного героя, контекст матча и нужные objective streams. Имена/account IDs не
запрашиваются. В прочитанной схеме у `players` есть только фильтр steamAccountId, поэтому
сетевой запрос читает playback игроков матча, а отбор по heroId делается до сохранения.

Записываются query/variables, время запросов, HTTP/GraphQL ошибки, SHA-256 ответа и самого
скрипта. `complete` относится к выполнению запросов/плану, не к пригодности координат:
даже null playback не означает ошибку транспорта. Пропущенные поля находятся в
`plan.omitted`, неполный результат сохраняется с `partial` и exit code 1. При закрытой
introspection guessed-запросов не будет. Для запроса и чтения body действует 30s timeout.
Authorization не сохраняется; токен остаётся только в локальном окружении.

PowerShell, Node с поддержкой `--env-file`, уже настроенный `.env.local`:

```powershell
cd D:\dota-coach
git fetch origin
if ($LASTEXITCODE -ne 0) { throw 'Не удалось получить ветку' }
git switch research/stratz-coordinates-50
if ($LASTEXITCODE -ne 0) { throw 'Не удалось переключить ветку; выгрузку не запускать' }
git pull --ff-only origin research/stratz-coordinates-50
if ($LASTEXITCODE -ne 0) { throw 'Ветка не обновлена; выгрузку не запускать' }
$capturePath = Join-Path $env:TEMP ('stratz-coordinates-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.json')
node --env-file=.env.local scripts/probe-stratz-coordinates.mjs '9019592113:42' '9003795847:42' "--out=$capturePath"
$captureExit = $LASTEXITCODE
if (Test-Path $capturePath) {
    Get-Item $capturePath | Select-Object FullName, Length
    Get-FileHash -Algorithm SHA256 $capturePath
    Write-Host "Код завершения: $captureExit. Непустой partial JSON также нужен для исследования."
} else {
    Write-Host 'Новый файл не создан; нужен текст ошибки без токена.'
}
```

Файл не перезаписывается, если уже существует. Next.js запускать не нужно. Прислать только
получившийся JSON; `.env.local` и токены не присылать. Команда не повторяет benchmark/cohort
исследование. При недоступности старых матчей запустить тот же скрипт с **явными**
`Match ID:hero ID` двух свежих матчей с доступными реплеями, желательно по одному за каждую
сторону. Их IDs заранее неизвестны и здесь не выдуманы.

Для проверки именно известных реплеев можно попробовать исходные URLs OpenDota в локальной
сети (успешное скачивание из этой среды не подтверждено):

```powershell
cd D:\dota-coach
$replayDir = Join-Path $env:TEMP 'dota50-replays'
New-Item -ItemType Directory -Force $replayDir | Out-Null
$replays = @{
    '9019592113' = 'http://replay185.valve.net/570/9019592113_1795309280.dem.bz2'
    '9003795847' = 'http://replay273.valve.net/570/9003795847_131812823.dem.bz2'
}
foreach ($matchId in $replays.Keys) {
    $file = Join-Path $replayDir "$matchId.dem.bz2"
    if (Test-Path $file) { Write-Host "Уже есть: $file"; continue }
    curl.exe --fail --location --connect-timeout 10 --max-time 180 --output "$file.part" $replays[$matchId]
    if ($LASTEXITCODE -eq 0) {
        Move-Item "$file.part" $file
        Get-FileHash -Algorithm SHA256 $file
    } else {
        Remove-Item "$file.part" -ErrorAction SilentlyContinue
        Write-Host "Реплей $matchId не скачан; HTTP/transport ошибку сохранить отдельно."
    }
}
```

Минимальный визуальный остаток — кадры/короткие клипы перечисленных эпизодов с видимыми
Match ID, выбранным героем, игровыми часами и всей миникартой; плюс точная версия карты.
Если сохранились `.dem`/`.dem.bz2`, достаточно сообщить имена и SHA-256, а для числовой
world-сверки предоставить реплей или извлечённые entity positions с game clock и версией
parser. Одного STRATZ playback достаточно лишь для проверки согласованности его собственного
рендера; независимый replay предпочтителен для world projection. Скриншот сегодняшней карты
без привязки к версии/матчу не годится.

## Проверки и self-review

- Автоматические проверки collector используют **синтетические** ответы: schema gating,
  выбор игрока, неоднозначность, partial HTTP/GraphQL, timeout при чтении body, сохранность
  null/пустых/неполных пар и повторов, отсутствие токена и отказ перезаписать файл. Они не
  проверяют реальные координаты. Команда: `npm run test:stratz-research`.
